## 当前执行路径

默认区间墙钟模式使用 runtime_native_loop.py 与 runtime_native_executor.py。Windows x64 / MuJoCo 3.3.2 下，编译循环直接调用原生 MuJoCo；500 Hz 热路径不调用 Python、不持有 GIL、不写磁盘。每个微步保留完整积分状态匹配、模型和载荷 SHA-256、2 ms 实际应用窗口，以及实际步后的实现检查。

独立规划进程直接取得首个真实微步后的状态与原始采集时间，预测已提交前驱剩余九步的终点，包含运动目标，并直接发布双缓冲槽。Python 协调器不参与逐段请求释放或发布。只有活动段和待交接段，没有过期候选队列。

每段仍包含原 17 维 QP、十步原补偿力矩预演、全部包络与下一起点检查。ADMM 编译保留递推、罚参数更新、停止条件和容差，关闭 fast-math；舍入可能不同，必须新做独立验收。安全距离、形状域、执行器限制与 1e-9 状态容差保持。

证书绑定来源、前驱、真实执行器模型/配置、材料区间、预测起点与完整载荷；发布截止和执行覆盖分别固定，发布后不改写年龄。槽采用 acquire/release 原子状态转移，只有空槽可被写入。迟到、失配或覆盖耗尽均拒绝，没有零动作或旧动作续期。

工作区/JIT 初始化后重新采集完整状态，单独验证启动段，预声明 100 ms 后启动任务；此前模型未启动动力学。这一启动条件不能推广到正在运动的硬件。

实际数据只通过 67 路 ctrl 与原生 mj_step 演化。原生状态、实际力矩和 QPC 时间保存在 native/<scenario>.npz。观察日志由事后新建 MuJoCo 数据从初始状态和实际力矩重放，逐状态核对原生记录后生成；预演状态没有写入真实执行器。

## 新候选的独立代码核对

审查发现并修复了四项运行时问题：来源时间数组对非整段时长向上取整，避免原生越界；所有合同时间显式拒绝 NaN/Inf；执行后状态失配记录真实尝试索引及已消费力矩，保留实际物理步数；事后记录接收具有超时，EOF/传输异常仍无条件尝试恢复调度、GC 和哈希资源，并保存已收到的记录。

验收入口单场景和五场景必须具有完整的 13,500 个物理步、1,350 段、正确场景集合与频率，以及发布和首次实际应用 p95 均不超过 20 ms。原 17 项通过或进程退出零不能代替这些资格条件。启动长尾仍保留在全量统计。前置资格失败时不进入正式重复。

独立审计将证书采集时间绑定到原生 acquired/source_times，首次应用时间绑定到完成 67 路 ctrl 写入后的原生消费时间，并从原始时钟重算 p95/p99/max、超限数和连续超限。拒绝后的真实积分状态须与最后捕获状态逐元素精确相等；只核对计数不足以证明未继续推进。

这些修复不改变控制力矩、状态容差或 2 ms / 20 ms 门槛，也不将旧物理试验变成新候选的墙钟通过记录。默认 HIGH 策略仍保留五场景失败；可选 REALTIME 条件即使通过，也须明确平台前提并验证最终默认入口，才能满足默认墙钟目标。

## 平台条件与验收入口

已运行原生试验采用 Windows HIGH_PRIORITY_CLASS、互不重叠的物理 P 核集合、BLAS 单线程与循环期禁用 GC；只作用于本次进程/线程，结束后恢复。[Windows 优先级规则](https://learn.microsoft.com/en-us/windows/win32/procthread/scheduling-priorities)不提供本任务的截止保证。

当前普通进程不具有 SeIncreaseBasePriorityPrivilege。c11_qualified_preflight_01/scheduler_preflight.json 记录了请求实时优先级而实际类未达到要求，预检失败且没有启动物理。代码只启用令牌已有权限并恢复，不给账户新增权限。

run_c11_qualified_acceptance 在干净冻结提交上预声明：当前/历史测试 → 单场景 → 五场景 → 三轮五场景 → 四组完整独立验收。前置资格失败时不启动正式重复；源码稳定时，正式重复中的场景或计时失败仍保留并执行三轮。每个步骤/轮次前后都核对声明提交与源码清单，源码变化后剩余轮记录为未启动且整套失败，不能拼接不同候选。输出目录不可覆盖。

若批准管理员条件试验，可在管理员 PowerShell 中从本仓库运行：

    .\.venv\Scripts\python.exe -m v6_lite.run_c11_qualified_acceptance --wall-scheduler-policy realtime --output-dir v6_lite/output/runs/c11_qualified_admin_01

仅实验进程临时使用声明优先级，预检核对实际 API 结果，不修改系统全局配置。执行器线程基准 24、规划线程 23、协调线程 17；其余核心保留给系统和交互应用。[Microsoft API 文档](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setpriorityclass)说明实时优先级可能影响响应，因此必须显式记录这些条件。有限经验通过也不构成硬实时、连续时间安全或可靠备份控制证明。
