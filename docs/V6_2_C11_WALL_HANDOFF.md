## 首次失效定位

开发基点为 `fbfa9f62a0855cf19485d5929e90b1c2fc7647d4`，分支为 `v6.2-c1.1-wall-handoff`。

五个原 C.1 墙钟失败均发生在首段斜坡中途。发布剩余有效期依次为 1.890、2.487、2.198、3.044、2.705 ms；拒绝子步依次为 3、4、4、5、5。完整原始时间线、失败记录、哈希和事件表保存在 `v6_lite/output/v6_2_c11_first_rejection_v2/`。

源码和记录共同确认：原路径串行完成规划和预演，再执行斜坡，而证书只覆盖从采集起的 20 ms。该窗口同时消耗于计算和实际力矩步。原短记录不能证明长期相位漂移或稳态抖动的根因。

## 调度与覆盖

执行器按绝对单调时钟运行 2 ms 更新；独立进程在当前段执行时规划下一段。只有一个活动段和一个待交接段，结果槽容量固定为 2 MiB，执行器不等待 IPC 锁。每段仍包含一个 17 维 QP、十步原伺服力矩预演、所有包络与下一起点检查。

下一起点使用已提交前驱的原生预测 `Phi` 终点。该缓存绑定前驱 ID 和完整积分状态，包含目标卫星；当前实际起点以及每个实际微步均必须匹配。预测状态只进入私有规划数据，实际数据仅通过真实力矩和 `mj_step` 演化。

命令分别记录发布截止、执行起点和覆盖终点，以及来源状态、前驱、模型、配置、区间、预测起点和全部控制载荷哈希。发布后数组由不可写的 bytes 支撑。迟到、乱序、重复或身份不匹配的包不能执行；覆盖耗尽时记为 `NO_VALID_CONTINUATION`，没有零动作、过期端点续用或安全备份的声明。

启动工作区与 JIT 初始化在正式任务之外完成。随后重新读取完整状态，单独规划并验证启动段，在预先指定的未来任务起点进行实际状态检查；保留原采集时间。本试验模型在正式起点之前未启动动力学。这一启动条件属于仿真试验范围，不能用于声称正在运动的硬件也具有同样的启动保证。

原安全距离、执行器限制、形状域和数值容差保持。ADMM 编译实现保留原递推、罚参数更新和停止条件，未启用 fast-math。三角求解的舍入可能不同，因此新轨迹必须重新经过独立物理与合同验收，不能直接继承旧轨迹的结论。

## 声明的平台条件

当前成功单场景采用 Windows 自身进程的 `HIGH_PRIORITY_CLASS`、独立逻辑处理器上的规划/执行线程、BLAS 单线程和绝对截止时间末尾主动等待。循环期间禁用周期垃圾回收，结束后恢复。参数和 API 成功状态将逐场景记录，所有设置只作用于实验进程，并在结束时恢复。Windows 的[优先级规则](https://learn.microsoft.com/en-us/windows/win32/procthread/scheduling-priorities)和[线程亲和性规则](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setthreadaffinitymask)不提供本任务的硬实时保证。

Numba 0.61.2 与本仓库 Python 3.12 / NumPy 1.26 的组合在其[版本支持表](https://numba.readthedocs.io/en/0.61.2/user/installing.html#version-support-information)范围内；依赖固定在 `requirements.txt`。
