# HTDCR 源码与当前自由漂浮项目：独立核查及调整

日期：2026-10-19。依据 GitHub 插件读取的仓库信息及全新只读源码快照 `900d781ba63f0123dff95e49a76d51cb49a74803`。没有读取项目内其他对话；当前项目对照只使用源代码、数据索引和保存的原始探针结果。本报告由 AI 辅助核查、编写。

## 结论

参考项目的主线是**关节起终构型条件下的廉价平滑多路径先验 → 执行器约束修正 → 条件去噪学习 → 采样时多步约束引导 → 独立硬验收**。不能把它概括为“网络裸生成就稳定到达任意世界目标”，也不能概括为“先为每个任务运行完整物理专家认证”。

当前项目的轻量前向先验方向可以保留。最关键的不同是：参考网络已知终点关节构型，并在采样中反复硬写入边界；当前网络面对双末端世界位姿，自由漂浮基座的最终位姿取决于整条路径。其次，参考方法在多次去噪迭代中引导，而当前 `ff_prior_latent.learning.sample` 只在最终干净预测上调用一次共同修正器。训练世界终点损失是当前项目的适配研究，**并非参考代码实现该机制的必要训练步骤**。

因此调整为：保留合格先验和旧开发模型；分别推进受控的终点学习诊断与去噪内引导；分别报告网络贡献、完整规划机制、独立物理执行。不能靠一个加权终点损失的下降替代5 mm／1°合格率，也不能把共同修正器的成功全部归功于网络。

## 论文能确认到什么程度

出版社可检索到同名论文：Changlong Zhang、Jinxin Liu、Bingquan Wang、Zhihang Fu、Naijin Liu，*Robotics and Autonomous Systems* 207，105754，期次标为2027年1月，DOI `10.1016/j.robot.2026.105754`。可访问的摘要及章节预览说明：在B样条控制点空间生成多候选，去噪中使用避障、执行器与目标约束；小角度条件下使用常量绳索雅可比，并报告仿真和六段样机实验。[出版社页面](https://www.sciencedirect.com/science/article/pii/S0921889026004252)

## 1. 粗数据如何生成

入口是 `scripts/training/generate_training_data.py`，不是RRT、IK或物理执行器搜索。

1. 默认实例化四段、每段四个离散节的机器人，以每段两个弯曲参数表示，共8维，范围±30°。
2. 独立均匀采样起点与终点关节构型。静态正运动学只计算对应末端位置；训练条件实际使用完整起终关节向量。
3. 每对默认5个槽位。槽位0是关节线性插值；其余使用六次多项式，随机中间时刻在0.2—0.8，中间构型为两端平均值加±0.1 rad扰动，约束起终速度、加速度为零。
4. 多项式在100个相位点采样，拟合20个控制点的三次夹持B样条。前4和后4个控制点分别固定为起终构型，中间控制点通过最小二乘拟合。
5. 非线性候选只在最终20个轨迹采样点检查关节范围，最多尝试100次。失败后回退线性轨迹，所以“5条”不保证5条不同的路径，更不保证5个障碍同伦类别。
6. 保存起终构型、位置、轨迹、控制点、节点和元数据。`__main__` 的默认值是100,000对，即500,000条槽位轨迹。这是程序参数，仓库没有对应完整训练数组与完成日志供核实。

此阶段没有障碍环境、绳索速度/加速度硬验收、自由漂浮动量传播或力矩执行。它首先提供运动分布，而非完整场景专家数据。[生成器](https://github.com/zhanglooong/htdcr-actuator-aware-diffusion-planning/blob/900d781ba63f0123dff95e49a76d51cb49a74803/scripts/training/generate_training_data.py#L237)

## 2. 执行器修正如何做

`refine_training_data.py` 读取已有五槽控制点，以10秒、100点轨迹计算关节与绳索约束。优化器是Adam，默认学习率0.015、最多180次迭代；损失包含接近原控制点、平滑、关节范围、绳索行程、速度及加速度惩罚。内部快速约束以常量绳索雅可比映射关节轨迹及导数；独立验收的行程使用非线性长度模型，速度和加速度仍采用配置指定的常量模型。

修正默认只固定第一个和最后一个控制点，**不是粗生成器的前后各4点**。这保持关节起终点，却可能改变原来的零速度/零加速度端点结构。优化前已满足快速条件的样本可以跳过，最后逐条调用独立硬验收，输出指标及失败列表。[修正器](https://github.com/zhanglooong/htdcr-actuator-aware-diffusion-planning/blob/900d781ba63f0123dff95e49a76d51cb49a74803/scripts/training/refine_training_data.py#L38)

该流程是无障碍开放空间修正。其硬阈值包括绳索行程±100 mm、速度2.5 mm/s、加速度约0.08333 m/s²；规划验收另有终点关节误差≤1e-4 rad与20 mm中心线避障门。它们不能直接替换本项目的仅不穿透、双末端世界5 mm／1°、完整67力矩执行及独立重放门。[原验收代码](https://github.com/zhanglooong/htdcr-actuator-aware-diffusion-planning/blob/900d781ba63f0123dff95e49a76d51cb49a74803/src/htdcr_planning/constraints/feasibility.py#L120)

## 3. 训练与采样分别承担什么

数据加载器按起终构型对分区，默认80%／10%／10%，同一对的所有模态留在一个分区。这一点值得保留。网络输入是带噪控制点、噪声时间、起点关节角、终点关节角，没有把完整障碍环境输入该主网络。

训练主损失是噪声预测MSE；主代码没有训练时逐样本真实世界终点损失，也没有在训练损失中执行力矩仿真。默认Transformer宽256、6层、16头，扩散1000步、batch256、500 epochs；这些也只是默认设置，实际使用的模型需以未提供的checkpoint配置为准。[训练损失](https://github.com/zhanglooong/htdcr-actuator-aware-diffusion-planning/blob/900d781ba63f0123dff95e49a76d51cb49a74803/src/htdcr_planning/models/DiffusionProcess.py#L120)

规划配置每任务5候选，DDIM声明60步，末18次采样迭代引导。实际时间序列用整除步长，若训练扩散1000步，`range(0,1000,1000//60)`实际产生63次。边界条件在初始化、去噪前后及最终输出多次写入前后各4控制点。引导使用避障、关节、绳索行程/速度/加速度和平滑成本，各项按配置做样本级归一化/裁剪。目标关节构型本身提供强边界约束，不能把硬写入边界后的精度全部解读为神经条件学习精度。[引导采样器](https://github.com/zhanglooong/htdcr-actuator-aware-diffusion-planning/blob/900d781ba63f0123dff95e49a76d51cb49a74803/src/htdcr_planning/interface/guided_sampler.py#L67)

参考项目的“Diffusion收益”应理解为其完整规划器的实验比较，而非由裸网络保证所有约束。本项目同样可以研究完整引导规划器，但必须用强样条和条件均值接受相同修正与验收，才能识别网络的额外贡献。

## 4. 此版本源码的复现缺口

这些是代码层证据，不足以据此断言作者实际论文实验使用了错误数据。

|项目|核查结果|本项目处理|
|---|---|---|
|五槽多样性|失败回退线性，可重复|明确统计独立路径；普通主库不强制五条，strict_multimodal仍按原合同|
|轨迹与控制点一致性|线性模式保存原线性点，而控制点是带端点约束的拟合结果|统一以重建样条为权威，另存原提案，禁止混名|
|修正后失败过滤|失败写CSV，但全部修正控制点仍写入输出数组|训练索引只准入逐条合格记录，失败保留隔离|
|数据接口|修正器把控制点也存成trajectories.npy；没有输出加载器必需的metadata.npy|显式schema、单位、数组语义和完整元数据|
|入口衔接|生成器默认输出、refiner输入、trainer默认输入目录不同；FeasibilityConfig.load默认路径缺失|不能声称三条默认命令已组成可复现闭环|
|归一化|统计在分区前对全数组计算；训练起终条件用joint统计，推理条件用control-point统计|本项目继续TRAIN-only codec；核对训练/采样同一条件编码，不能照搬潜在尺度不一致|
|边界结构|粗生成前后各4点固定，refiner默认各1点固定|独立验证完整初态及端点速度/保持，不能只看端点位置|
|实际资产|公开代码无完整训练集、权重与训练运行证据|500,000只写默认目标规模，不写已证实合格规模|

归一化的训练/推理不一致只有在两套统计不同的时候才产生数值影响；本次未取得原checkpoint，不能量化它对论文指标的实际影响。[加载器](https://github.com/zhanglooong/htdcr-actuator-aware-diffusion-planning/blob/900d781ba63f0123dff95e49a76d51cb49a74803/src/htdcr_planning/dataset/dataloaderConfig.py#L29)；[推理条件编码](https://github.com/zhanglooong/htdcr-actuator-aware-diffusion-planning/blob/900d781ba63f0123dff95e49a76d51cb49a74803/src/htdcr_planning/planning/diffusion_planner.py#L271)

## 5. 本次实际运行的源码探针

命令：`.venv\Scripts\python.exe -m ff_prior_source_alignment.audit_reference`。不运行原仓库CLI，不加载其冻结测试任务，不训练网络，也不执行本地机器人。源文件哈希前后一致。由于原默认验收配置路径不存在，本探针显式读取仓库实际存在的 `configs/robot/strict_verifier.yaml`，在无障碍条件下检查；未更改其数值阈值。

固定seed20261019，调用原函数生成8对×5槽=40条，默认四段8维、20控制点。按10秒、100点检查：修正前31/40合格，9条速度超限；原修正函数优化35次后39/40合格。剩余1条关节越界1.457e-8 rad，硬检查依然拒绝，没有放宽阈值。

此外，线性槽保存点与样条重建最大差0.078198 rad；非线性槽差0；强制max_attempts=0的五槽只有1条独立路径；本次1001点稠密检查没有发现原样条关节越界。修正后前后四控制点最大变化0.078988 rad，实证表明其默认修正并未保持全部四点边界。以上只说明这些函数在这40条新数值样本上的行为，**不是论文成功率，也不是本项目MODEL_VALID或执行通过数**。

原始逐条记录：`../evidence/reference_probe_001.json`。依赖tqdm缺失通过隔离目录安装解决，没有改动既有Python环境或使用stub。

## 6. 当前项目实际差异和瓶颈

|维度|参考版本|当前项目|
|---|---|---|
|条件|q_start、q_goal|17维初态特征＋双末端世界位姿＋时长，完整物理初态单独绑定|
|终点|静态基座下FK(q_goal)，采样硬写边界|T_world_base(T)·FK(q(T))，基座由整条运动与耦合传播决定|
|表示|20×8控制点；Transformer噪声预测|19×17自由参数，TRAIN拟合6个时间方向→102维残差，条件中心＋MLP v预测|
|多路径数据|同起终关节构型5槽，但可能重复|多数前向轨迹有各自派生世界目标；固定世界目标修正样本少|
|物理处理|主要执行器运动学可行性、采样多步引导|自由漂浮传播、全机几何、最终共同目标保持修正、预选真实力矩和重放|
|训练世界监督|主训练没有此项|局部G与完整102维当前预测梯度的适配研究|

自由漂浮中固定q_goal不够：即使q(T)相同，基座末态可以随路径变化。因此不能把私有教师轨迹的终点关节角当成推理已知条件，也不能固定基座来复现参考边界便利。它说明任务更难，不说明当前传播模型已经错误。

本次只读核对13886条源记录哈希、TRAIN/VAL家族分区与已有资格标签。13838 TRAIN对应13495精确任务，其中13405仅一条（约99.33%），90个有至少两条、71个有至少五条；“至少五条”是数量统计，未在本次重新证明几何多样性。VAL为48条、40任务，家族无交叉。TRAIN中13615条记录为MODEL_VALID、223条为EXECUTION_VERIFIED；这些是继承的记录等级，本次没有重做物理验收或升级任何样本。完整初态标识有1600种。

此结果支持继续使用已合格的运动先验，但不能保证给定世界目标的逆映射精度。样本稀疏是需要对照验证的假设，不是已经确定的唯一原因。表示容量、条件编码、局部/世界梯度尺度与采样引导都需要分别测试，不能简单归咎于微重力或数据“全部没法用”。

最新四组原始TRAIN探针重算：D的配对损失中位比0.914089，较B为0.853648；位置中位数8.77 mm，但姿态1.325°且同时合格4/32，低于旧5/32。旧门≤0.8失败保持BLOCKED。参考主训练无世界监督，意味着不能把这一适配分支成败等同于整个引导Diffusion机制成败；同样不能借参考项目为D自动晋级。

## 7. 已落实的调整与下一步

本次已新增可运行的来源探针、只读数据审计及**下一轮适用**的双臂终点准入计算器；10项软件测试通过。新计算器保留≤0.8及不劣于局部对照两条件，并检查同时合格数、已有合格探针回退和位置/姿态各自中位数，拒绝错误配对、NaN、缺失单臂与不一致损失。它只判定TRAIN诊断门，不是物理验证器，不触发DEV或TEST。

初版数据审计错误地要求VAL记录training_eligible=True，产生48条误报；已按TRAIN/VAL角色纠正并补测试。初版结果保留在local_alignment_001.json，正式结果为local_alignment_002.json（PASS），没有更改数据去迁就审计。

详细待实施方案见 `NEXT_PROTOCOL.md`：

1. 保持旧13774模型和当前已合格库；不先启动1024槽扩库，不重新跑失败的相同四组。
2. 优先隔离“最后一步修正”与“后期多步去噪内引导”：先在已有TRAIN任务上，用同一冻结模型、16网络调用、5候选和相同110次耦合修正总上限比较，不能给新方法额外隐形重试。两种强非神经基线使用相同物理修正与验收。
3. 世界监督作为独立学习分支继续：保留每批局部G，先做有界梯度尺度/步长诊断，再单独改变频率与噪声覆盖；不把网络梯度裁剪等同于实际AdamW步长缩放。它的DEV门仍须按已冻结协议通过，不能借机制分支绕过。
4. 数据补充优先重用已有固定目标修正轨迹；先评估重复覆盖的收益，再按TRAIN覆盖缺口小批补齐。保持主先验与固定目标多路径子集分开；只准入合格轨迹，拒绝失败后重标。主先验无需每目标五条；严格多模态子集规则不变。
5. 每阶段分别记录原始提案、共同预处理、去噪内引导、最终修正、独立模型验收、真实执行与重放。裸提案未全部合格不自动否定完整引导规划，但共同修正通过不自动证明Diffusion优势。

新协议目前为**待实现运行**，本次没有开展新训练或新DEV。原冻结任务与候选预算保持，所有历史结论、原始结果和旧模型保留。仅不穿透、5 mm／1°、17→67、完整初态、自由漂浮、全机几何、原始力矩及独立重放均不变。pilot、study、strict_multimodal、1024槽扩库和最终TEST均未启动。

## 证据边界

本报告是源码取证、数值函数探针和现有记录再统计，不是参考论文完整复现，也不是新一轮Diffusion收益实验。下一阶段不预设必胜。原始运行错误、审计修订及所有失败记录均保留；合格扩库和长期最终目标尚未达成。
