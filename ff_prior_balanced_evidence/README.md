# Balanced-scene body evidence

This package observes the one authorized new 2-rigid/5-continuum engineering unit. It never calls `mj_step`, changes actual states, replaces the full-machine acceptance backend, or produces unsourced successful trajectories.

`BodyObstacleRecorder(robot, scene_dict, source_mode='actual_control_tick', deadline=...)` resolves collidable geometries on both arm branches. `sample(data, command_before=None, command_after=None, active_constraints=None, filter_reason='', native_index=None)` queries the current measured state read-only. `save(out_dir, source_native_path=None, expected_samples=None, failure=None)` saves distances, exact nearest geometry IDs, connector endpoints, all body origins, curvature observations, commands and active-constraint events. Callers must preserve failures separately from original physical qualification.

Static integration: `record_saved_trace(robot, scene, native_path, out_dir, control_dt=.002, deadline=..., notify=...)` uses private scratch kinematics on every native control tick plus the final state. Static reference following has no online obstacle velocity filter; missing filter commands remain NaN and are explicitly described. Dynamic integration samples at every 0.02-second control tick, retains actual filter commands and all constraint records, and should also observe the final state once.

Every obstacle is tested against every collidable geometry on each arm branch, reduced only inside a named body. Each query uses center distance plus both geometry bounding radii plus one metre as an upper bound; a capped return raises. No fixed 2.5-metre cap or broad-phase omission is mislabeled as an exact distance. The 10-mm display band is not an acceptance threshold; physical nonpenetration remains zero and the original whole-machine checks remain authoritative.

Pure URDF inspection gives up to 72 collidable arm bodies / 76 geometries before compilation. Thus the static 13,751-state worst count is 7,315,532 exact queries; dynamic 1,351 ticks need 718,732. Static binary arrays are about 445 MiB uncompressed, below the 512-MiB diagnostic reservation. All seven-obstacle per-tick nearest-body CSV rows require roughly 10 MiB additional media output. Runtime metadata records actual compiled topology, query count, elapsed time and completion; deadlines produce an explicitly partial record. No timing claim is made before execution.

`generate_episode_media(out, robot, arrays, goals, scene, waypoints, diagnostic_dirs, deadline, notify, status, title, max_frames=420)` accepts saved arrays `time/qpos/qvel/ee/base`, optional `clearance_m`, and static or time-varying `goals`. Existing standard PNG/PDF plots and `timeseries.csv` in `out` are included. It creates body-distance heatmaps, per-obstacle distance and nearest-link curves, continuum shape/curvature plots, filter-delta curves where recorded, CSV tables, two videos and an interactive page. All videos use actual saved qpos and SE3; RGB axes and cumulative paths are present for both arms, W1-W7 remain marked, closest bodies and exact distance lines are shown. Highlight frames align exactly with diagnostic timestamps; missing diagnostics are labeled rather than interpolated into precise evidence.

Body distance and shape change are observations. They do not establish counterfactual benefit or network autonomy. Discrete centerline curvature is a body-origin geometry diagnostic, not material strain. Satellite motion is not invented.

`python -m ff_prior_balanced_evidence.test_software` checks pure math, schema and source invariants with synthetic fixtures only. It performs zero model compilation, geometry evaluations, coupled propagation or native steps.
