## 执行顺序

| 阶段 | 实际工作与交付 | 判定与下一步 |
|---|---|---|
| M0 已有证据承接 | 冻结当前合格数据、目标损失检查点、合同、原DEV/VAL身份；读取现有执行证据；封存TRAIN残差诊断 | 已有小规模可行性可承接，不为新计划重复训练或扫描幅度；不能推定跨场景泛化 |
| M1 全流程接口与碰撞闭合 | 审计数据加载→编码→加噪/去噪→DDIM→去噪内修正→独立验证→力矩→重放；高噪声/引导后float64边界回归；用预先按几何选择的TRAIN障碍案例检查引导方向和目标保持 | 只修复真实缺口。保存引导前后碰撞及目标误差；无碰撞案例不能证明碰撞引导有效。核心故障阻止其依赖的采样/训练，不阻止独立合格主库生成 |
| M2 首批有界扩库 | 目标累计约1,000条合格TRAIN，现有256条起算；新独立家族的前向派生目标为主，少量固定TRAIN目标修正为辅；逐条校验数组/初态/哈希/门槛/近邻隔离 | 新索引只收合格样本；完整保留拒绝与已知执行失败。达到数量或预算上限即止，如实报告缺口；不恢复同目标至少五条限制 |
| M3 扩库后的实际学习与采样 | 继承可行表示/损失；归一化只拟合TRAIN；记录每条新增数据实际曝光、权重变化、检查点身份；冻结采样种子和预算后验证 | 不以训练loss或某个成本百分比作为完成依据；不使用DEV挑检查点；不把网络调用移除后仍命名Diffusion |
| M4 冻结smoke、物理抽查和交付 | 保留原DEV四任务，固定每任务五候选；强样条、同数据均值、目标损失Diffusion使用相同公开条件/修正器/验证器；预选候选执行和独立重放；生成中文报告和可恢复作业 | 报告每任务与每种子成功/失败、候选合格率、目标误差、物理等级。小规模通过支持继续分阶段扩库；不宣称最终TEST、硬件验证或全域优越性 |

## 下一运行的资源与协议冻结要求

以下是下一独立后台作业的规划上限，必须在其可执行配置中落实并核对，不能把本Markdown当作已执行记录：

- 首阶段数据目标约1,000 TRAIN，新增提案最多1,200；至少覆盖150个新TRAIN家族为设计目标，未达到时报告实际覆盖，不用重复模式替代。固定目标修正不超过新增尝试的20%。主库沿用审计支持的静态场景/零初始动量范围，完整保存状态，不宣称任意初始动量支持。
- 整轮上限2小时、2 CPU计算线程、新增本地文件上限20 GiB；达到上限停止该阶段并记录未完成项。无无限补样、隐式重试或自动升规模。具体控制点幅度、初态分布、场景分层、随机种子和生成准入必须先落入冻结配置；新覆盖不能按Diffusion是否独赢挑选。
- 最多16条新增数据分层预选力矩执行/独立重放；选择规则在看到执行结果前固定，失败不替换。仅通过的单条升级EXECUTION_VERIFIED，已知失败排除训练，其余保持MODEL_VALID。
- 复核预设3组采样种子，原DEV四任务、每任务五候选、三方法；最多180候选、36次选中执行/独立重放。不需要为当前扩库先做多个训练种子的全面研究；正式优越性声明另行确认。
- 下一轮稳定性判据在运行前固定：每组种子的Diffusion候选合格率至少90%，每个任务至少有一个合格候选，所选执行与独立重放全部通过，且无未解决的非有限值、越界或数据泄漏。失败只阻止“稳定闭合通过”的声明和进一步无审计放量，不删除已独立合格的数据，也不改物理阈值。
- 查询、时间、存储均完整记录，预算内不要求比样条、均值或HTDCR更低。不同方法共享上限；任何额外引导都如实核算。
