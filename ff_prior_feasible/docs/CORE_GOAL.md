## 当前执行顺序与必须交付的结果

1. **先跑通并稳定 Diffusion 完整机制。** 合格轨迹生成与独立准入 → 公共初态和指定世界目标条件编码 → TRAIN-only归一化及训练 → 稳定的加噪/去噪与DDIM更新 → 去噪内目标/碰撞/执行器约束引导 → 独立MODEL_VALID验证 → 选定候选真实67通道力矩执行 → 完整初态独立重放。必须实际读取数据、更新模型权重、调用网络采样并保存中间证据。Diffusion与物理引导组成的规划器可以作为完整方法；不额外要求未经引导的网络裸输出全部合格，但必须分别报告修正前后质量和贡献。
2. **最终实际扩库。** 形成可训练、可恢复生成、有质量分层和来源审计的扩展数据集，并用其实际完成训练与复核。扩库是必须交付的终局结果；不能仅交付扩库脚本、空索引、建议或一直停留在数百条样本。

两项必须实际交付。已有证据足以支持小规模方案可行时，直接进入有界扩库，不重做无必要的成本消融，也不等待所有基线均被击败。软件测试通过不能代替执行证据，局部smoke可行不能写成全域可靠。当前小规模证据与新阶段证据分开；具体受阻阶段保留BLOCKED原因，并继续不依赖它的工作。

**优越性仍是研究目标，但不是启动扩库的先决条件。** 优先观察指定世界目标成功率、复杂任务覆盖、合格率、稳定性与轨迹质量。耗时和耦合查询次数保留为辅助诊断和资源核算，不再要求降低固定百分比、低于参考项目或低于每个基线。资源上限用于避免失控运行，不等于相对效率胜出门槛。不得为满足预期制造优势；没有收益就如实报告“优势未成立”，不将已经成立的机制可行性一并否定。

## 优越性验证的完成依据

若要正式宣称优越性，再单独冻结确认协议；至少3组采样种子，并在可控预算下检查不同训练种子。该确认不阻塞合格数据扩库。保留全部任务、失败、正反向独赢和实际成本，不按结果临时更换指标。需要区分运动先验、目标修正、碰撞引导、新数据与新权重的贡献。

优势可以由预注册的任务或质量指标体现；仅在选择效率作为具体研究主张时，才检验相对效率：

- 难例覆盖：在独立冻结的开发验证任务家族上提高任务成功率；同时报告样条独赢的反向案例和多种子一致性。
- 计算效率：在任务成功率与合格候选率不降时，实际耦合查询及候选墙钟耗时均降低；主张不能只依赖相同预算上限。

具体效应大小、任务数与统计标准在确认轮开始前冻结；本轮正在运行的协议不追溯修改。本项目最终TEST继续保留，当前证据明确标注开发验证范围。

## 扩库必须包含的内容

- 大主库：平滑样条提案、廉价筛选、自由漂浮传播、前向派生并冻结世界目标，独立验证后入MODEL_VALID库。主库不恢复“同目标至少五条”门槛。
- 难例修正子集：少量固定TRAIN世界目标，补充真正有效的绕行、较大运动及初态变化；根据消融决定是否引入障碍条件编码或保持场景无关先验＋物理引导。
- 分级物理证据：预先选定的分层子集做真实67力矩执行与独立重放，只有相应单条升级；未执行样本保持MODEL_VALID。
- 可用数据交付：实际数组、完整初态、17→67映射、模型/几何/约束版本、家族与分区、失败清单、来源哈希、验证等级、训练加载计数、覆盖统计和恢复状态。
- 训练复核：扩库后实际加载新增数据训练，并复跑冻结对照；数据更多不自动意味着收益成立。
